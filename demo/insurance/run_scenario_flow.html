What happens on each pass through for _ in range(max_rounds): state = app.invoke(state) — the three ways the loop can end, and the two ways it feeds itself back in.

decision / partial-return path success path state mutation

Why a round cap

Without max_rounds, an agent stuck asking for the same field forever — or a followup script that never satisfies it — would hang the scenario indefinitely.

Two different "unfinished"

A round-limit exit and a StopIteration exit both return a partial final_application, but for different reasons — worth distinguishing when debugging a scenario that didn't complete.

State carries forward

Nothing resets between iterations — state from one invoke is fed directly into the next, so applicant_data, risk_flags, etc. accumulate across rounds.
